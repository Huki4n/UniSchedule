# UniSchedule

Настольное расписание ИТИС для Windows. Доска показывает пары выбранной недели и ближайшее занятие, месяц — домашки с комментариями. Пары и домашки открываются в боковой панели: изменение предмета можно применить к одной паре или к серии, сегодняшнее название можно вернуть. Импортирует Excel и напоминает о начале пары.

Этот проект — эксперимент с полным использованием агентной разработки.

Стек: .NET 10, WPF, SQLite, ClosedXML.

Поведение по областям: [docs/README.md](docs/README.md) — запуск, взаимодействие, расписание, домашки, подгрузка, уведомления, хранение.

## Требования

- Windows 10 или новее
- [.NET SDK 10](https://dotnet.microsoft.com/download)
- GNU Make (`make`)

## Команды

Из корня репозитория. `make` без цели печатает тот же список.

| Команда | Что делает |
| --- | --- |
| `make build` | Собрать приложение в Release |
| `make test` | Прогнать тесты Release, все категории |
| `make test-unit` | Тесты Release без категории `E2E` |
| `make test-e2e` | Только сквозные тесты Release |
| `make run` | Запустить приложение. База — в профиле пользователя |
| `make build-debug` | Собрать Debug, если запущенное приложение держит Release-exe |
| `make test-debug` | Прогнать тесты Debug, все категории |
| `make test-debug-unit` | Тесты Debug без категории `E2E` |
| `make test-debug-e2e` | Только сквозные тесты Debug |
| `make import FILE=file.xlsx OUT=report.txt` | Импортировать Excel в базу профиля уже собранным Release-exe |
| `make data DB=D:\temp\schedule.db` | Запустить со своей базой, не меняя автозапуск Windows |

Готовый файл: `UniSchedule\bin\Release\net10.0-windows10.0.17763.0\UniSchedule.exe`.

## Запуск

Из корня репозитория:

```text
make build
make run
```

`make run` собирает Release и открывает окно. База — `%LocalAppData%\UniSchedule\schedule.db`.

Своя база, без смены автозапуска Windows:

```text
make data DB=D:\temp\schedule.db
```

Каталог файла создаётся. Другой путь `--data` открывается вторым окном. Повторный запуск с той же базой показывает уже открытое.

Если Release-exe занят запущенным приложением, `make run` не пересоберёт его. Выход — из меню трея, когда включено «сворачивать в трей».

## Импорт

Файл — `xlsx` расписания ИТИС. Берётся лист, в имени которого есть «Расписание», иначе первый. Повторный импорт заменяет только ранее импортированные пары во всей базе. Пары, добавленные вручную, остаются. Выбранная группа не переключается. Если её нет в файле, она остаётся пустой.

В окне кнопка «Импорт Excel». Диалог открывается в «Загрузках». Пока идёт разбор, доска не кликается. В конце — «Импортировано пар: N из M групп.» Ошибка разбора базу не меняет. Успешный импорт закрывает боковую панель.

Без окна, уже собранным Release-exe. Оба параметра обязательны:

```text
make import FILE=file.xlsx OUT=report.txt
```

Окно не открывается, запись идёт в базу профиля. Отчёт:

```text
OK groups=<число групп> lessons=<сколько записано> links=<сколько пар получили ссылку звонка>
group=<выбранная группа>
<код группы>
```

Ошибка — строка `ERROR` и текст исключения.

Импорт в свою базу:

```text
UniSchedule\bin\Release\net10.0-windows10.0.17763.0\UniSchedule.exe --import file.xlsx --out report.txt --data D:\temp\schedule.db
```

## Данные

База хранится в `%LocalAppData%\UniSchedule\schedule.db`. Если рядом с exe ещё лежит старый `schedule.db`, при следующем запуске он переносится в профиль.

Повторный импорт заменяет только ранее импортированные пары. Пары, добавленные вручную, остаются.

`--data` открывает указанный файл и запускает отдельный экземпляр. Ключ автозапуска Windows при этом не меняется.

Второй запуск с той же базой не открывает новое окно, а показывает уже работающее. Закрытие окна при включённом «сворачивать в трей» прячет приложение. Выход — из меню трея.

Напоминание приходит в интервале от `начало − N минут` до двух минут после этой отметки. Смещения задаются списком минут. Пустой список — автонапоминаний нет. Ноль в список не попадает и не подменяется на 60 или 15.
