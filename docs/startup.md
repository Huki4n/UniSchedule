# Запуск

Точка входа — `App.OnStartup` в `UniSchedule/App.xaml.cs`. Аргументы читаются из `ArgsOverride`, если тесты его задали, иначе из командной строки.

## Порядок

1. Подписка на необработанное исключение UI. Текст пишется в `%TEMP%\unischedule-crash.txt`. Диалог показывается один раз, пока предыдущий не закрыт.
2. `--import` обрабатывается без окна и завершает процесс. См. [loading.md](loading.md).
3. Из `--data` берётся путь к базе. Без аргумента база — профиль пользователя. См. [storage.md](storage.md).
4. Захватывается mutex. Если экземпляр с этой базой уже есть, выставляется событие «показать» и процесс завершается.
5. Создаётся `AppDatabase`, настройки читаются и сразу записываются обратно (нормализация даты и значений по умолчанию).
6. Автозапуск Windows применяется только для базы профиля.
7. Стартует `NotificationService`, показывается `MainWindow`, создаётся трей.
8. Фоновый поток `UniSchedule.ShowListener` ждёт событие «показать» и вызывает `ShowMain`.

Ошибка на шагах 2–8 пишется в тот же crash-файл, показывается диалог «Ошибка запуска», процесс завершается.

## Аргументы

| Аргумент | Эффект |
| --- | --- |
| `--import <файл.xlsx>` | Разбор Excel и запись в базу, затем выход. Окно не открывается. |
| `--out <отчёт.txt>` | Куда писать отчёт импорта. По умолчанию `%TEMP%\unischedule-import.txt`. |
| `--data <путь.db>` | Открыть этот файл. Каталог создаётся. Старая база рядом с exe не переносится. Ключ автозапуска Windows не меняется. |

`make import` и `make data` собирают эти аргументы. См. `Makefile`.

## Установка

`make installer` публикует Release `win-x64` со встроенным runtime и собирает `dist/UniSchedule-Setup.exe` скриптом `installer/UniSchedule.iss` (Inno Setup 6). Отдельный .NET на машине не нужен. Компилятор скрипта — Inno Setup, без него цель не собирается.

`UniSchedule-Setup.exe` ставит приложение текущему пользователю в `%LocalAppData%\Programs\UniSchedule`. Права администратора не нужны. Мастер на русском: каталог и установка. В меню «Пуск» появляется «Расписание». В «Установленных приложениях» пункт «Расписание», удаление оттуда.

Каталог установки не совпадает с каталогом базы. `schedule.db` лежит в `%LocalAppData%\UniSchedule` и при удалении остаётся. Значение `UniSchedule` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` удаляется, только если оно указывает на установленный exe.

`make install` по-прежнему копирует публикацию в `%LocalAppData%\UniSchedule\app` без мастера. Если exe из этого каталога запущен, копирование останавливается. `make uninstall` снимает только эту копию и её ярлык, базу не трогает.

Автозапуск из настроек по-прежнему пишет путь текущего exe.

## Один экземпляр

Имена считает `AppLaunch`.

| База | Mutex | Событие |
| --- | --- | --- |
| Профиль | `Local\UniSchedule.SingleInstance` | `Local\UniSchedule.Show` |
| `--data` | `Local\UniSchedule.` + 16 hex SHA-256 полного пути | `Local\UniSchedule.Show.` + тот же токен |

Разные файлы `--data` запускаются параллельно. Второй процесс с тем же файлом будит первый: окно показывается, восстанавливается из свёрнутого и активируется.

Выход из трея ставит `App.IsExiting`, сигналит событие и вызывает `Shutdown`. На выходе останавливаются таймер уведомлений и трей, mutex отпускается, только если его захватил этот процесс.

## Композиция

`App` владеет базой, `NotificationService`, `MainWindow` и `TrayService`. Окно получает флаг `manageAutostart`: он истинен только без `--data`. Сохранение настроек при `--data` пишет флаг `Autostart` в эту базу и не трогает `HKCU\...\Run`.

`AutostartService` пишет значение `UniSchedule` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`: путь текущего exe в кавычках, либо удаляет значение.
